# Violet Archive

Violet Archive — серверный плагин для Purpur 26.3. Игрокам не нужны ресурс-пак и клиентский мод. Плагин не подменяет измерение Края.

Те же сведения по-английски лежат в [README.md](README.md).

## Требования

- Java 25
- Purpur 26.3
- Maven

Зависимость API — `org.purpurmc.purpur:purpur-api`, область `provided`. Maven берёт её из `https://repo.purpurmc.org/snapshots`. На сервере этот API уже есть, поэтому в jar Purpur не упаковывается.

В `paper-plugin.yml` указаны `api-version` `26.3`, версия плагина `1.0.0` и загрузчик `violetarchive.bootstrap.VioletArchiveBootstrap`.

## Сборка

Из корня репозитория:

```bash
mvn -q clean package
```

Готовый jar: `target/violetarchive-1.0.0.jar`.

`mvn test` запускает модульные тесты из этого репозитория. Они не поднимают сервер Purpur.

## Установка

Скопируйте `target/violetarchive-1.0.0.jar` в `plugins/` сервера и перезапустите его.

При первом включении плагин записывает `plugins/VioletArchive/config.yml` из файла по умолчанию. В конфиге одна настройка — дистанция следования Анимы:

```yaml
anima:
  follow-distance: 4.5
```

`4.5` — значение по умолчанию. Число от `0.5` до `64`, включая границы, сохраняется. Если ключа нет, значение не число или оно вне этого диапазона, плагин пишет предупреждение в лог и берёт `4.5`. Значение читается при включении плагина. Команды перезагрузки нет: после правки файла нужен перезапуск.

Если отладочную команду не вызывают, обычная игра не меняется.

## Что находят игроки

Структуры появляются во внешних биомах Края: `minecraft:small_end_islands`, `minecraft:end_midlands`, `minecraft:end_highlands` и `minecraft:end_barrens`. Центрального биома `minecraft:the_end` в этом списке нет. Набор `violetarchive:archive` ставит `violetarchive:library` и `violetarchive:tower` с равным весом: случайный разброс, spacing 32, separation 16, тип `triangular`. Зона исключения в 8 чанков держит их в стороне от `minecraft:end_cities`.

Оба здания — джигсоу-структуры из датапака. Шаблон библиотеки — частично разрушенное здание: западная сторона открыта, в палитре есть паутина, треснувший каменный кирпич, книжные полки и вишнёвое дерево. Шаблон башни — целая постройка 9×18×9. Фундамент из кирпича эндерняка лежит внизу этого шаблона. У башни `start_height.absolute` равен `2`, у библиотеки — `0`. Обе сажаются на `WORLD_SURFACE_WG`. Эти высоты действуют для новых чанков. Уже сгенерированный чанк заново не переписывается.

Охраняемый сундук библиотеки использует таблицу лута `violetarchive:archive/vault`. Шалкер рядом с ним называется **Purpur Watcher**, красится в фиолетовый, становится постоянным и получает 45 здоровья. Пока игрок в пределах 32 блоков, вокруг смотрителя крутятся четыре предмета-отображения с осколком аметиста. Плагин отменяет пулю шалкера смотрителя. Залп начинается, если смотритель уже не прыгает и не стреляет, с прошлого залпа прошло 60 тиков и в радиусе 5 блоков есть хотя бы два подходящих твёрдых блока. Бедрокк, барьеры и сундуки не берутся. Залп поднимает два таких блока. Блок, дошедший до выбранного игрока, наносит 4 урона, а потом встаёт на место. Пока игрок остаётся в пределах 6 блоков, примерно одна попытка из четырёх начинает прыжок. Прыжок поднимает блок, на котором сидит смотритель, и затем возвращает этот блок. При приземлении игроков в пределах 3.5 блока отталкивает и может превратить часть земли в кольце вокруг сиденья в аметист, с несколькими маленькими почками. С бедрока, барьера, сундука и нетвёрдого блока прыжка нет. Страж башни так не ведёт себя.

Сундук башни использует `violetarchive:archive/tower`. Его шалкер называется **Archive Sentry**, красится в фиолетовый и становится постоянным. Здоровье, пулю и телепорт стража плагин не меняет.

У охраняемого сундука и его шалкера один общий `violetarchive:lock_id`. Ключ в сундук не кладётся. Смерть смотрителя или стража добавляет подходящий ключ архива к дропу этого моба.

В шаблоне библиотеки есть и обычные сундуки: `swords`, `bows`, `armor`, `tools`, `depths`, `mending`, `curses` и `supplies`. Их таблицы остаются в JSON датапака. Там ванильные вещи и книги, в том числе золотой шлем с проклятием привязки, железный нагрудник с проклятием утраты и книга Починки с шансом 15%. Незерита, Клинка Смотрителя и Vindicta в этих таблицах нет. Плагин запирает только сундук хранилища и сундук башни.

Когда сундук хранилища выдаёт лут, плагин добавляет один Клинок Смотрителя, если таблица его ещё не положила. Клинок — алмазный меч с данными `violetarchive:watchers_blade`. У него нет рывка, скачка, лишнего урона и другой атаки. Для сундука хранилища и сундука башни плагин ещё с шансом 8% добавляет зачарованную книгу Vindicta. Этой книги нет в JSON лута. Брошенная книга Vindicta недолго поднимается вверх.

Vindicta, Ration и Anima — три зарегистрированных зачарования. У каждого максимальный уровень 1.

- **Vindicta** садится на кожаный, медный, кольчужный, железный, золотой, алмазный и незеритовый нагрудники, а также на элитры. Оно несовместимо с Шипами, и Шипы несовместимы с ним. Когда живая сущность бьёт владельца, с шансом 20% вылетает помеченная пуля шалкера. Попадание этой пули наносит 6 урона, даёт левитацию на 60 тиков с усилителем 0 и без частиц и добавляет горизонтальный толчок 0.12 от владельца. Остальные пули шалкера, включая пулю стража, остаются ванильными.
- **Ration** садится на любой ящик шалкера и несовместимо с Anima. В таблицах лута его нет. Раз в секунду, если игрок несёт ящик с Ration и не держит открытым ящик шалкера, плагин тратит из него не больше одного предмета. При здоровье не выше 40% или при вредном эффекте он может выпить одно обычное зелье либо ведро молока, если вредный эффект ещё остался. Взрывные и туманные зелья не трогает. Лечащее зелье пьёт только при низком здоровье. Другое полезное зелье пьёт только если такого эффекта у игрока ещё нет. При голоде ниже полного съедает одну еду, которая закрывает нехватку, и выбирает наименьший избыток.
- **Anima** садится на любой ящик шалкера и несовместимо с Ration. В таблицах лута его нет. Поставленный ящик запоминает игрока, который его поставил. Каждые 10 тиков, если этот игрок в сети в том же мире, ящик дальше 2 блоков, а глаза игрока в пределах дистанции следования, ящик шагает на один блок по большей горизонтальной оси. Сначала пробует ту же высоту, потом блок выше, потом блок ниже, и поворачивает крышку на четверть оборота. Если ящик сломать, зачарование возвращается на выпавший предмет.

Имена предметов рисует сервер из `lang/en_us.json` и `lang/ru_ru.json`. По-английски это "Watcher's Blade" и "Archive Key". По-русски — "Клинок Смотрителя" и "Ключ архива". Текст обычный, не клиентский ключ перевода, а описание без курсива. Имя снимается, когда предмет уходит из инвентаря игрока. Имена мобов остаются английскими строками выше.

Дальше 1024 блоков от центра примерно одна из пяти внешних клеток может стать аметистовым лесом. Клетка — квадрат со стороной 200 блоков. Чанк подходит, если его центр дальше 1024 блоков от `x=0, z=0` и значение клетки попадает в нижние 20%. Лес — не структура. При первой генерации популятор красит верхний эндерняк в шахматную клетку из кальцита и аметиста, ставит биом колонки `violetarchive:amethyst_forest` и может поставить стволы из кальцита, крону из аметиста и кальцита, почки и стержни Края. Уже сохранённые чанки повторно не украшаются. Чанк, где уже есть пурпуровый блок, пурпуровая колонна, пурпурное стекло или кирпич эндерняка, пропускается. В JSON биома заданы туман `#4A3270`, частицы стержня Края и фиолетовой пыли и спавн эндерменов. Список особенностей биома пуст: деревья ставит популятор. Эндерняк под поверхностью остаётся на месте.

## Замки

Замок сундука — безымянный осколок аметиста. Единственные лишние данные — строка `violetarchive:lock_id`. У осколка нет имени предмета и описания.

Ключ архива — тоже осколок аметиста. В нём лежат `violetarchive:archive_key` и тот же `lock_id`. Когда игрок держит ключ, на нём может появиться нарисованное имя. Это имя не входит в замок.

Ключ может лежать в любой руке. Сундук открывается только если `lock_id` ключа совпадает с `lock_id` сундука. Ключ от другого сундука, именованный осколок без данных плагина и голый осколок аметиста не подходят. Такие нажатия оставляют ванильный отказ запертого контейнера (`container.isLocked`). Замок с сундука не снимается.

Совпадение проверяется, когда меню сундука спрашивает замок. Нарисованное имя на ключе эту проверку не ломает: сравнивается идентификатор замка, а не имя предмета.

## Отладочная команда

`/violetarchive` регистрируется в Java в момент создания объекта плагина. В разделе `commands` файла `paper-plugin.yml` её нет. Право — `violetarchive.debug`, по умолчанию `op`, описание: "Run Violet Archive debug checks."

Команду должен вводить игрок. Консоль получает отказ. Если команду никто не вызывает, обычная игра не меняется. Существующие подкоманды:

| Команда | Действие |
| --- | --- |
| `/violetarchive` | Печатает имена подкоманд. |
| `give blade` | Выдаёт Клинок Смотрителя. |
| `give key` | Ставит рядом запертый сундук и выдаёт его ключ. |
| `give decoy` | Выдаёт именованный осколок аметиста без данных плагина. |
| `give vindicta` | Выдаёт книгу с хранимой Vindicta. |
| `give chestplate` | Выдаёт алмазный нагрудник с Vindicta. |
| `give elytra` | Выдаёт элитры с Vindicta. |
| `give ration` | Выдаёт наполненный ящик шалкера с Ration. |
| `give anima` | Выдаёт фиолетовый ящик шалкера с Anima. |
| `spawn watcher` | Создаёт Purpur Watcher на небольшой площадке и выдаёт ключ. |
| `spawn sentry` | Создаёт Archive Sentry на небольшой площадке и выдаёт ключ. |
| `locate library` | Печатает библиотеку дальше 1024 блоков. |
| `locate tower` | Печатает башню дальше 1024 блоков. |
| `locate forest` | Печатает чанк леса. |
| `tp library` | Телепортирует к библиотеке. |
| `tp tower` | Телепортирует к башне. |
| `tp forest` | Телепортирует на поверхность леса. |
| `trigger volley` | Запускает залп смотрителя. |
| `trigger jump` | Запускает прыжок смотрителя. |
| `trigger vindicta` | Пускает пулю Vindicta в ближайшего моба. |
| `trigger ration` | Делает одну проверку Ration. |
| `trigger anima` | Делает один шаг Anima. |
| `loot chest <table> [count]` | Ставит от 1 до 64 сундуков с настоящей таблицей `violetarchive:archive/<table>`. |
| `inspect` | Печатает локаль, дистанцию, предмет в руке, цель и сведения о чарах. |

`<table>` — это `swords`, `bows`, `armor`, `tools`, `depths`, `mending`, `curses`, `supplies`, `vault` или `tower`. `locate` и `tp` загружают мир `world_the_end` и создают его, если такого мира нет. `trigger` вызывает те же игровые методы, которыми пользуются живой смотритель, Vindicta, Ration и Anima.

## Чего плагин не делает

- У Клинка Смотрителя нет боевой способности.
- Плагин не регистрирует рецепты крафта.
- Центральный остров, дракон Края, города Края и корабли Края не подменяются. В датапаке нет `data/minecraft/dimension/the_end.json`.
- Vindicta, Ration и Anima регистрируются в Java при загрузке. В датапаке нет JSON зачарований. Регистрация не помечает их как находимые за столом зачарований и не отдаёт их жителям.
- Ration и Anima не добавляются в генерируемый лут. В обычной игре книгу Vindicta можно найти в сундуке хранилища или башни. Ящик с Ration или Anima там не появляется.
- Структуры и биом `violetarchive:amethyst_forest` приходят из датапака внутри jar. В `pack.mcmeta` указан `pack_format` `121.0`. Загрузчик находит этот пакет как `violetarchive`.

## Пакеты

| Пакет | Содержимое |
| --- | --- |
| `violetarchive` | Включение плагина, дистанция следования и ключи данных в `Keys`. |
| `violetarchive.bootstrap` | Поиск датапака и регистрация зачарований. |
| `violetarchive.item` | Замок архива, ключ, Клинок Смотрителя и нарисованные имена. |
| `violetarchive.structure` | Доделка структур, Purpur Watcher и добавочный лут хранилища и башни. |
| `violetarchive.enchant` | Vindicta, Ration и Anima. |
| `violetarchive.world` | Решение об аметистовом лесе и популятор чанков. |
| `violetarchive.debug` | Команда `/violetarchive`. |
